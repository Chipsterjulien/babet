# Babet 2.33.0 en préparation — GUI, lot 1

Date : 24 octobre 2026. Base : tag `v2.32.0`, commit
`45274f98016252f4da9232cf06607b528de00d24`.

## Périmètre livré

- `gui.picture` et ses cinq méthodes : chargement/remplacement/effacement d'une
  image, ajustement, réduction, dimensions intrinsèques et texte alternatif.
- `picture` utilisable avec les méthodes communes, `onDrag` et `setDragData`.
- `gui.openFile` et `gui.saveFile` asynchrones, filtres, parent modal,
  dossier/nom initial, sélection multiple et retours d'erreur.
- Annulation à la destruction du parent, à la sortie de `gui.run()` et à la
  fermeture de l'état Lua ; résultat natif tardif libéré sans rappel de Lua.
- Tests, documentation FR/EN, exemple générique `examples/gui_picture/main.lua`.

Les lots 2 et 3 ne sont pas implémentés : DND de fichiers, tags TextView,
presse-papiers image, miniatures, launchers et rappels idle/timeout restent à
traiter après validation de ce lot. Aucun tag ni publication GitHub n'a été créé.
CMake prépare la version **2.33.0** ; les changelogs la gardent dans Unreleased.
Les README distinguent cette branche de développement de la 2.32.0 publiée.
Les manuels PDF seront régénérés à la finalisation de la release.

## Compatibilité et décisions

| Fonction | GTK minimal |
|---|---|
| Picture vide, effacement, réduction, dimensions, texte alternatif | 4.0 |
| Texture chargée depuis un fichier | 4.6 |
| Ajustement explicitement demandé, même `contain` | 4.8 |
| Sélecteurs de fichiers | 4.10 |

Les nouveaux symboles sont optionnels. Les API existantes et le DND par chaînes
conservent leur comportement. Sans option explicite d'ajustement, une Picture
utilise le mode natif qui conserve les proportions.

Un sélecteur sans parent peut garder `gui.run()` actif sans fenêtre Babet.
L'annulation par l'utilisateur appelle le callback avec `nil`. La destruction
du parent, la sortie de boucle et la fermeture Lua annulent silencieusement les
opérations en attente. Le callback est protégé, y compris la construction des
chaînes et tableaux Lua. Une sélection multiple non locale échoue entièrement.

`saveFile` choisit un chemin, sans écrire de fichier. Le chargement d'image est
synchrone ; aucune miniature ou isolation du décodeur n'est ajoutée dans ce lot.

## Vérifications réalisées

Les essais utilisent les vrais fichiers GUI/chargeur de Babet et Lua 5.5.1 dans
un exécutable ciblé ; seuls les services de signaux et l'état curses y sont
remplacés par des stubs. **Ce n'est pas une compilation complète de Babet ni un
passage complet de `./run_tests.sh --release`.** Cette validation reste à effectuer
sur le projet de Julien.

| Vérification | Résultat |
|---|---|
| Compilation C++23, `-Wall -Wextra -Wpedantic -Werror` | PASS |
| Images/sélecteurs sur faux GTK, normal puis ASan/UBSan | 24/24 dans chaque mode |
| Widgets existants sur faux GTK, normal puis ASan/UBSan | 74/74 dans chaque mode |
| Tests d'allocation et callbacks, normal puis ASan/UBSan | 8 groupes PASS dans chaque mode |
| GTK 4.14 réel sous Xvfb, normal puis ASan/UBSan + fatal-criticals | 5/5 dans chaque mode, aucun SKIP |
| Chargeur dynamique autonome, y compris anciens faux GTK | 17/17 |
| Contrats GUI widgets / runtime / conception | 140/140, 35/35, 33/33 |
| Syntaxe shell/Python et `git diff --check` | PASS |

Les 24 cas couvrent les capacités GTK absentes, les arguments invalides,
le maintien de l'image après échec, les cinq acquisitions natives pouvant échouer,
la sélection simple/multiple, l'annulation, les fichiers non locaux, les erreurs
et yield dans les callbacks, la réentrance, le démarrage depuis une coroutine,
la fermeture explicite/GC du parent, `gui.quit()` et la fermeture de Lua.

Les nouveaux balayages d'allocation couvrent :

- Picture : 8 cas Lua en échec et 88 témoins ;
- création de sélecteur : 29 cas Lua en échec et 67 témoins ;
- résultat de sélecteur : 5 cas en échec et 27 témoins ;
- allocations C++ et récupération après erreur ;
- compteurs de widgets/GObject, GError et copies de chemins revenant à zéro,
  y compris après traitement d'une réponse native suivant `lua_close()`.

Les cinq essais sur GTK réel vérifient PNG et JPEG, dimensions 80×40 et hauteur
selon la largeur, ouverture, sélection multiple (un fichier choisi via le
clavier ; le faux GTK couvre deux fichiers ordonnés), sauvegarde et annulation.
Le test vérifie aussi que `saveFile` ne crée pas le fichier. Ici, Xvfb a utilisé
une connexion TCP locale faute de sockets Unix disponibles ; le pilote livré
utilise le serveur privé standard du projet.

### Limite de la détection des fuites

LeakSanitizer a échoué dans l'environnement de préparation avec une erreur
`/proc/.../task` et un diagnostic de type ptrace. Les passages ASan/UBSan locaux
ont donc utilisé `detect_leaks=0` : ils vérifient les accès mémoire, pas une
absence générale de fuites. Les compteurs du faux GTK vérifient séparément les
ressources possédées par Babet. Le script d'injection livré ne désactive pas
LeakSanitizer ; la validation locale peut donc l'utiliser si l'environnement le
permet. Le test sur GTK réel applique la politique existante du projet : pas de
LeakSanitizer sur les caches des bibliothèques système, ASan/UBSan conservés.

## Application et retour attendu

Extraire le ZIP **à la racine du projet 2.32.0**, en remplaçant les fichiers et en
conservant les nouveaux fichiers `.inc`. Aucune suppression n'est requise.
L'archive ne contient ni build, ni binaire Babet, ni journaux, ni caches Python.

Puis, depuis la racine :

```bash
./run_tests.sh --release
```

Transmettre `babet-tests.txt`. Si GTK est trop ancien ou si Xvfb/XTest manque,
les essais réels concernés affichent explicitement SKIP ; les tests sur faux
GTK restent exécutés. Il ne faut pas publier la 2.33.0 avant la validation et
la décision sur les lots suivants.
