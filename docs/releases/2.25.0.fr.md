# Publication de Babet 2.25.0

La 2.25.0 publie le lot Entry : nouvelle API de saisie texte, callbacks et
correction des cycles de durée de vie des widgets. Une version mineure
correspond à cet ajout de fonctionnalité. Les anciens tags restent inchangés.

L'implémentation a passé le `--release` transmis le 6 octobre et l'exemple
graphique semble fonctionner sur le poste du mainteneur. La préparation de
cette release concerne les versions et la documentation ; `src/` est inchangé
depuis cette validation. Le binaire 2.25.0 reste à reconstruire et vérifier.

## Fichiers alignés

- CMake : `project(babet VERSION 2.25.0 LANGUAGES CXX C)`.
- README, changelogs et index des manuels français et anglais.
- Manuels PDF régénérés avec le chapitre GUI et Entry, auparavant omis de la
  liste des chapitres ; liens internes GUI/curses/WebSocket corrigés.
- Le préprocesseur PDF appelé par Python doit être lisible ; le bit exécutable
  n'est plus exigé inutilement.
- Le texte de release anglais est extrait du changelog dans
  `dist/release-notes.md`, hors des sources suivies, conformément à `RELEASING.md`.

Extraire le ZIP à la racine du projet en remplaçant les fichiers. Il contient
uniquement les fichiers ajoutés/modifiés depuis le lot Entry déjà appliqué.

## Commandes à la racine du dépôt

Vérifier `git status` avant d'exécuter le bloc : les modifications suivies et les
éventuels changements déjà indexés seront inclus dans le commit. Les nouveaux
fichiers du lot Entry et ce guide sont ajoutés explicitement. Les ZIP, caches,
produits de build et notes dans `dist/` ne sont pas ajoutés.

Le bloc utilise la branche courante. Il teste avant de créer le tag et pousse
le commit/tag ensemble. Une erreur arrête le sous-shell sans fermer le terminal.
`release.sh` refait `dist/` : conserver ailleurs les artefacts d'autres
architectures avant cette étape si nécessaire.

```bash
(
  set -euo pipefail
  babet_release_version=2.25.0
  babet_release_tag="v${babet_release_version}"
  babet_release_branch="$(git symbolic-ref --quiet --short HEAD)"

  git fetch origin --tags
  if git show-ref --verify --quiet "refs/tags/${babet_release_tag}"; then
    echo "Le tag ${babet_release_tag} existe déjà : arrêt sans le modifier." >&2
    exit 1
  fi

  test "$(sed -nE 's/^project\(babet VERSION ([0-9.]+) LANGUAGES CXX C\)$/\1/p' CMakeLists.txt)" = "${babet_release_version}"
  ./run_tests.sh --release
  test "$(./test/babet --version)" = "babet ${babet_release_version}"

  git diff --check
  git add -u
  git add -- GUI_ENTRY_LOT1.fr.md examples/gui_entry/main.lua \
    tests/gui/entry_contract.lua tests/gui/entry_events.lua \
    tools/test_gui_entry.py docs/releases/2.25.0.fr.md
  git diff --cached --check
  git commit -m "Release Babet ${babet_release_version}: GTK Entry and callback lifetimes"
  test "$(git show HEAD:CMakeLists.txt | sed -nE 's/^project\(babet VERSION ([0-9.]+) LANGUAGES CXX C\)$/\1/p')" = "${babet_release_version}"
  git tag -a "${babet_release_tag}" -m "Babet ${babet_release_version}"

  ./release.sh --version "${babet_release_version}"
  awk '/^## \[2\.25\.0\]/{active=1;next} /^## \[/{if(active)exit} active' \
    CHANGELOG.md > dist/release-notes.md
  test -s dist/release-notes.md
  git push --atomic origin "HEAD:refs/heads/${babet_release_branch}" "refs/tags/${babet_release_tag}"
)
```

Si la fabrication des artefacts ou le push échoue, le commit/tag local peut
déjà exister. Corriger la cause et reprendre cette étape, sans recréer ni forcer
le tag ; ne pas relancer aveuglément tout le bloc.

## Créer la release GitHub

Après le push réussi, créer une release depuis **v2.25.0** :

- titre : **Babet 2.25.0 — GTK 4 text input** ;
- texte : contenu de `dist/release-notes.md` ;
- pièces jointes : fichiers de `dist/` pour l'architecture compilée, y compris
  les archives runtime/SDK, leurs SHA256 et les notices ;
- ajouter `docs/manual-fr.pdf` et `docs/manual-en.pdf`.

`dist/release-notes.md` sert au texte de présentation, inutile de le joindre
également comme pièce jointe. GitHub propose les archives de code source.
Pour d'autres architectures, compiler/tester nativement le même tag et ajouter
leurs artefacts à cette release. Aucun binaire ARM n'a été compilé ou validé ici.

## Passer à une autre discussion

Transmettre le nouveau `docs/manual-fr.pdf` et indiquer **Babet 2.25.0**. La GUI
disponible comprend window, box, label, button et entry avec les méthodes du
manuel. GTK 4 doit être installé sur la machine qui exécute l'application.

La future application de suivi du poids peut déjà utiliser SQLite et Entry.
SpinButton, Calendar et DrawingArea ne sont pas encore implémentés : ce sont
les prochains lots. Le manuel ne doit pas être interprété comme un binding GTK
générique donnant accès à tous ses widgets.
